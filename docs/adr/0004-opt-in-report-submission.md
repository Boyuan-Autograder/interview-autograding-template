# ADR-0004: 报告单自主提交官网（opt-in，零认证公开端点，荣誉系统）

**Date:** 2026-08-13
**Status:** Accepted

## Context

社团官网招新系统需要收集候选人的报告单，用于评测总览 / 榜单展示（官网侧 ADR-0001：公开端点 + 荣誉系统）。issue #6 的原始草案是在 `grade.yml` 解密步骤后自动 POST 报告到官网——候选人每次 push 报告单都会自动进入官网。

讨论后否决“默认上传”：报告单含候选人的得分明细，属于个人数据；**自动上传**把“提交”这个动作从候选人手里拿走。决议：上传必须是候选人的显式选择，默认不进官网。

## Decision

1. **`grade.yml` 不做任何推送改动**：解密的 Job Summary 自反馈路径保持不变，与官网路径彻底解耦。
2. **新增独立手动工作流 `upload.yml`**（`on: workflow_dispatch`）：候选人在派生仓 Actions 页面对 “Upload report to official site” 点一次 **Run workflow** = 显式提交；不点 = 永不进官网。
3. **上传前解密门控**：先跑 `npx autograding decrypt` 校验报告单；解密失败（损坏/被篡改/文件缺失）→ 工作流失败，不 POST。“只推有效报告”。
4. **载荷** = 加密报告单原始字节 base64（`autograding_report.json`，即密文信封，官网侧自行解密）+ `github.actor` / `github.repository` / `github.sha`，POST `https://official.boyuan.club/api/public/evaluations`（以官网契约为准）。不推解密明文。
5. **POST 失败语义 fail-fast**：非 2xx → 工作流变红，作为候选人的重试信号；重复提交由官网按报告内容 sha256 去重保证安全。
6. **安全边界显式化**：端点零认证 + 密钥公开（荣誉系统），任何持密钥者可伪造任意报告直 POST 官网；因此榜单/总览为**自愿采样 + 招新参考**，非权威判定（与现状安全模型一致，不引入新风险）。

## Rationale

- **隐私优先**：得分数据是否进入官网由候选人自己决定，不默认共享。
- **身份零妥协**：`github.actor` / `github.repository` / `github.sha` 由 GitHub 原生提供，无需本地解析。
- **改动面最小**：模板仓新增一个工作流文件；工具仓零改动；`grade.yml` 不动，原自反馈链路零回归风险。
- **提交动作显式可见**：一次可见的点击，而不是藏在旗标/文件里的隐式行为；重试 = 再点一次。
- **原草案的 `continue-on-error` 理由消失**：它存在的意义是不阻断 Job Summary 自反馈；独立工作流里没有这一步，失败应该显式可见。
- 与官网侧 ADR-0001（荣誉系统）一致：本 ADR 只决定“谁、何时”提交，不改变安全模型。

## Consequences

- 官网数据为**自愿采样**，不完整——排行榜/总览只能覆盖主动提交的候选人。
- 候选人多一步操作（一次点击），由 README 承担操作引导。
- 端到端烟测不自动触发上传步骤（会向生产端点发真实报告）；上传链路在官网联调时人工验证。
- 端点 / 载荷格式变更属跨仓契约变更（官网侧 openapi + 工具仓 #7 冻结契约），须在 issue #6 留痕后同步。
